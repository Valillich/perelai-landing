## Решение владельца и область утверждения

Владелец поручил подготовить U70 и оставить текущую длину региональных summary.
Это разрешение на подготовку пакета, **не утверждение итоговых строк**. `approvalRef: null`,
`runtimeApprovalGranted: false`; `APPROVED` нигде не присваивается.

На утверждение представлены 44 UI-ключа × 9 языков (RU/UK/EN/PL/ES/FR/DE/PT/TR),
описание размещения и три состояния согласия. Существующие строки приложения извлечены
дословно. Добавлены пять предлагаемых ключей, отсутствующих в локалях:

| Ключ | Причина включения |
|---|---|
| `legal_trader_address_label` | Сейчас sheet/страница используют English fallback “Registered address:” |
| `legal_contact_email_label` | English fallback “Business contact:” |
| `legal_privacy_contact_label` | English fallback “Privacy contact:” |
| `legal_refund_link` | English fallback “Refund policy” в custom-пути |
| `legal_terms_changed` | English fallback при revision conflict; предложен нейтральный текст об изменении условий без неверной атрибуции только бизнесу |

[Предлагаемые добавления](u70-booking-copy-20261008/candidate-additions.json) применены **только
в capture fixture**. В реальных локалях приложения они пока не установлены. Если пакет
утверждён, установить именно эти строки до проверки утверждённого manifest/hash.
Переводы проверены редакторски на смысл, плейсхолдеры и согласованность; это не отметка
проверки носителями языка или самостоятельного юридического утверждения. Никаких переводов
полных юридических документов здесь нет.

## Три состояния и размещение

| Состояние API/UI | Размещение | Содержание и действие |
|---|---|---|
| Первое принятие / `acceptanceRequired`, `termsUpdated: false` | Sticky footer после завершения содержания | Один пустой чекбокс; отдельная ссылка на Booking Terms; новая запись подтверждается отдельно |
| Обновлённые условия / `acceptanceRequired`, `termsUpdated: true` | Там же, сообщение над чекбоксом | Текст об обновлении + тот же пустой чекбокс; ранее принятые версии не выдаются за актуальные |
| `alreadyAccepted` | Там же, строка вместо чекбокса | Ссылка на Booking Terms + исходная дата принятия; отдельное подтверждение новой записи |

Повторное использование допустимо только по серверно проверенному personal Client в той же
Company и исходному affirmative evidence с совпадающими **terms version и copy version**.
Строки `PERELAI_TERMS_REFERENCE` и marketing evidence сами не дают повторного согласия.
Браузер при reuse не подставляет `perelaiBookingTermsAccepted: true`; сервер повторно проверяет
исходный evidence в транзакции и пишет reference с исходным `acceptedAt` и новым `referencedAt`.
Согласие с custom-условиями бизнеса требуется отдельно. Смена Client/Company или версий
прекращает reuse; revision conflict очищает локальное согласие и обновляет projection.

Дата: `Intl.DateTimeFormat(normalized UI language, {day: 'numeric', month: 'long', year: 'numeric',
timeZone: company.timezone})`. В `<time datetime>` сохраняется исходный timestamp. В примерах
используется `2026-10-08T09:00:00.000Z`, `Europe/Kyiv`; даты по девяти языкам приведены в таблицах.
Если timezone в projection отсутствует, текущий Intl использует timezone браузера; это
фактический fallback, а не новый продуктовый контракт.

Принятие относится к использованию Booking Service, включая последующие записи при совпадающих
версиях, в рамках существующего опубликованного [Booking Terms §1](../../../content/legal/en/booking-terms.md).
Утверждающий рассматривает этот способ повторного использования вместе с текстом и размещением;
пакет не переписывает платформенные Terms и не утверждает факт нового согласия на каждую запись.

## Privacy, документы и недоступность

- Комментарий находится перед Privacy и появляется после завершения содержания, независимо от согласия.
  Автоматическая прокрутка один раз показывает комментарий (`block: end`) без подсветки Privacy.
- Privacy информационный: полный текущий региональный summary дословно + роль Perelai + обе ссылки
  до отправки. При внешнем уведомлении — роль бизнеса и публичный контакт вместо generated summary.
- Generated notice открывается в ActionSheet с иконкой документа. Внутри — пояснение о языке при
  несовпадении, полное уведомление, версия/дата, контакты и permalink. Один скроллер, Escape и возврат фокуса.
  Текущий sheet может при фокусировании permalink открыться у конца документа; кадры начала получены
  прокруткой к началу. Это не обещание автоматического открытия на первом абзаце.
- Полный документ и напоминание сохраняют опубликованный язык. Перевод языка интерфейса их не меняет.
  Кнопка sheet не имеет языкового суффикса; пояснение размещено внутри документа.
- Попытка первого касания/Enter/Space/drag без согласия показывает один localized error, прокручивает
  к Privacy, подсвечивает её и фокусирует пустой чекбокс; “Tap again” не взводится.
  После согласия доступны Enter/Space, два касания в течение 3 секунд или drag.
- Ссылка Terms не переключает чекбокс. Чекбокс 18px, строка ≥44px, текст 13px, видимый keyboard focus.
  `aria-disabled` действия отражает отправку; guard защищает отправку до согласия.
- Недоступный intake заменяет форму и sticky footer одной карточкой с публичными email/address,
  без внутренних причин. Уже существующие визиты и fallback-ссылки остаются. Телефон не придумывается.
- Нет маркетингового чекбокса или утверждения «вы прочитали». Web не отправляет `marketingOptIn`.
  Запасная информационная фраза из 08 §5.3 **не предлагается к включению и не входит в canonical JSON**.

## Канонизация и воспроизводимость

Canonical JSON — только объект `locale → full.translation.key → exact string`.
UTF-8, рекурсивная сортировка ключей, `ensure_ascii=false`, разделители `,`/`:`, без BOM,
отступов и завершающего перевода строки. Unicode не нормализуется; пунктуация и плейсхолдеры
сохраняются. `sha256` берётся от этих точных байтов. `copy.json` — удобная форматированная копия.

Проверка пакета из этой директории:

```sh
python3 u70-booking-copy-20261008/verify.py --app /Users/valery/Sites/beauty-finance
```

Хеш canonical охватывает все 44 ключа на каждом языке, включая пять предложений.
В `artifacts.json` отдельно перечислены хеши spec snapshot, текстов, условий съёмки, screenshot index
и самих снимков. Это фиксирует контекст для человеческого утверждения; runtime legal manifest
`content/legal/versions.json` остаётся прежним.

[Read-only harness](u70-booking-copy-20261008/preview/README.md) сохранён для воспроизведения.
Полная исходная locale-база не дублируется: её SHA-256 зафиксированы в approval-record.

## После вашего явного утверждения

1. Записать approvalRef, дату и выбранную immutable copy version; сохранить утверждённый пакет.
2. Применить пять кандидатных переводов в приложение и добавить web manifest + drift test для
   всех включённых ключей; при изменении текста выпустить новую версию, не перезаписывать старую.
3. Обновить `.env.example` точной версией и ссылкой на approval record. Production ENV — отдельно владельцем.
4. Проверить на стенде projection/intakeAvailable, original evidence и reuse reference,
   а также неизменённую серверную проверку legalRevision. Выполнить release UI checks.

Для утверждения достаточно в этом чате явно указать пакет `u70-booking-copy-20261008.r1` и согласие
с текстами/тремя состояниями. Статус будет изменён только после такого подтверждения.
